# Interaction and scene-aware motion: model research

Checked against the authors' released repositories on 2026-09-26. This is a research shortlist, not a benchmark of these models in StageZero. No new checkpoint or training dataset was downloaded for this review. VRAM figures below are stated only when the authors publish them; otherwise a 48 GB GPU is a test target, not a guarantee.

## Recommendation for a weekend experiment

Build the **scene planner and contact measurements first**, then run an isolated **InterGen** pair-generation comparison for handshake/embrace and an **InterControl** contact-target comparison. InterGen is the fastest way to see a learned, synchronized two-person performance because its released checkpoint and `tools/infer.py` take one interaction caption. Its CC BY-NC-SA 4.0 license makes this a research demo, not a production dependency. InterControl is more useful if the director must place each person and specify which hands meet; it supplies spatial-control checkpoints and an example LLM contact-plan format. Its code is MIT, while its SMPL, CLIP, and dataset dependencies retain their own terms. [InterGen repository, demo, and license](https://github.com/tr3e/InterGen), [InterControl repository and setup](https://github.com/zhenzhiwang/intercontrol).

The most direct published architecture for a future responsive actor is **ReMoGen**: it generates an ego person's reaction conditioned on another person, scene geometry, or both, using separate released modules. Its currently published rollout scripts expect processed Inter-X, LINGO, or EgoBody sequences and the licensed SMPL-X body model; the repository does not state a code license. Treat it as a contained research experiment until its asset access, inference without dataset examples, and use terms are resolved. [ReMoGen repository and checkpoint instructions](https://github.com/4DVLab/ReMoGen).

Two larger systems merit later investigation. [ReMoGen](https://github.com/4DVLab/ReMoGen) supplies **human-human, human-scene and combined human-human-scene** adapters, released weights and autoregressive rollout. Its authors use Python 3.8/PyTorch 2.1/CUDA 11.8/PyTorch3D 0.7.5 and require processed scene occupancy plus SMPL-X assets, so a generic StageZero arch mesh is not directly a valid input. [Sitcom-Crafter](https://github.com/WindVChen/Sitcom-Crafter) combines a scene-aware two-person generator with locomotion, human-scene motion, plot understanding and collision correction. Its authors state around **12 GB** GPU memory suffices for evaluation and use Apache-2.0 code, but the full demo also requires Replica/PROX-S data, SMPL variants, DIMOS and COINS weights, and compiled `pointnet2_ops`/PyTorch3D. It is a valuable architectural reference and a high-integration-cost model test.

For scene locomotion, [DIMOS](https://github.com/zkf1997/DIMOS) releases pretrained collision-aware locomotion policies and a walk-to-object-then-interact demo, including examples with sofas/beds. It depends on prepared PROX/Replica scenes and SMPL-X assets; walking through a newly generated arch would still need scene conversion and a target path. The [scene-affordance model](https://github.com/afford-motion/afford-motion) likewise releases pretrained weights and links text to scene affordances, but its preprocessed data and older CUDA/PyTorch environment add setup cost. Neither recognizes object names in StageZero by itself.

## Where intelligence belongs

For “go through the gate,” three distinct jobs must connect:

1. **Ground the words in the current scene.** StageZero already stores stable object IDs, names, kinds, position and size in [`scene_objects.py`](../scene_objects.py). A language model can translate the sentence into a constrained plan such as `{actor_id, verb: "traverse", target_object_id: "arch-0"}` and ask for a choice only if the scene has ambiguous matching objects. A vision model adds value when an imported mesh or image has no reliable semantic label. Its result still needs a validated scene object, transform and collider. Text alone gives no evidence that the motion generator has seen the gate.
2. **Plan a traversable route.** An arch must expose an actual aperture and facing plane, not merely the existing enclosing box. Compute approach and exit anchors on opposite sides, inflate obstacle shapes by actor radius, check opening width/head clearance, and route the root through those anchors with the StageZero native root-waypoint control. Reject clips whose root misses the aperture or whose body intersects the posts. This should be geometry-led so a renamed arch behaves identically.
3. **Generate and correct the performance.** ARDY/Core can provide gait and gestural style between waypoints; a constrained IK/contact pass can place a hand on a prop handle and hold feet. For an actual grab, the object should attach only after measured contact, then move with the hand and detach at a scripted release frame. A dedicated human-object model may improve the pose, but cannot replace object state or collision logic. Two characters additionally need shared event times and contact targets, rather than two independent text prompts.

The planner can expose simple inspectable records: `scene_snapshot`, `actor_role`, `target_id`, `approach_anchor`, `exit_anchor`, `event_frames`, `contact_points`, `motion_model`, and `validation`. An AI API is well suited to parsing the director's prose into this schema, choosing role beats (approach, pause, exchange, leave), and ranking visually different candidate takes. Numeric route finding, collision tests and final contact validation should remain deterministic. This gives the user a readable reason when “gate” maps to the wrong object or a character cannot fit.

## Bounded experiments and pass conditions

1. **Gate crossing on the current rig.** Create one arch with an explicit opening and one nearby wall, place the actor on one side, and run 10 held-out seeds each for free text and planned approach/exit root goals. Measure aperture crossing (root changes sides inside opening), minimum capsule/post clearance, wall penetration, foot sliding, seam speed and fraction of clips completing the exit. Inspect at least three successes and all failures at full resolution. This tests scene understanding and route control without pretending ARDY accepts meshes directly.
2. **Two-person contact.** For 10 seeds each, compare independent ARDY actors, InterGen paired motion and InterControl joint plans on `shake hands, step apart` and `one helps the other up`. Retarget all to the same viewer scale and synchronize their clip timelines. Measure minimum head/torso separation, hand-to-hand distance during the intended contact window, contact duration, foot sliding and overlap. A handshake only counts if hands approach, meet, stay together for a beat, then separate without torso penetration. InterGen's non-commercial license confines its output to a research preview until usage terms are resolved.
3. **Prop contact.** Use an existing ball or door with a defined handle/contact point and explicit attach/hinge state. Compare ARDY native hand targets plus IK against one InterAct sample if its released checkpoint can accept the chosen mesh/class. Count hand-point error before attachment, object-hand drift during hold, floor penetration and successful release. An on/off proximity trigger alone is not evidence of a grasp.
4. **ReMoGen feasibility probe only if the first two expose a real model gap.** In a separate runtime, fetch only its published checkpoint modules and the minimum required licensed example assets; first reproduce the authors' sample rollout. Then test one novel partner trajectory and one converted simple scene. Profile peak VRAM and generation latency before choosing a GPU. The authors' HHSI code is promising but their examples depend on processed datasets, so “live arbitrary StageZero scene input” is an integration task, not a documented turnkey feature.

Keep every trial's prompt, object transforms, seed, model/checkpoint revision, runtime, raw poses and failure reason. Report exact denominators and use the same viewer/camera for competing clips. The current single-actor ARDY checkpoint has no scene geometry or partner-motion input, so its independent two-person output cannot establish learned social or object-aware motion; StageZero's prior [interaction probe](MOTION-INTERACTIONS-RESEARCH.md) measures that baseline.
